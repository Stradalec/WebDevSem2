# Веб-разработка, семестр 2. Back-end проект "EduPlatform".
## Автор: Калинин А.А.
### Описание

Back-end для платформы онлайн обучения. Учителя и ученики, создание курсов с уроками, запись и просмотр материалов.

### Запуск

start_dev - поднять все контейнеры в docker, подождать, пока оживёт Кафка, создать топики, поднять основной API и обработчик изображений.

stop_dev - снести контейнеры. Терминалы с API и обработчиком закрываются вручную.

### Архитектура

Есть два сервиса:

1. Main API

Вся бизнес-логика обитает здесь. Авторизация, создание курсов и уроков, запись на них, загрузка изображений, кэширование - всё это здесь.

Кратко о том, что есть:

Авторизация через JWT-токен. Лучше сессионой модели тем, что не надо заваливать БД кучей записей об одном пользователе. Пользователю дали токен поиграть, через N времени он истёк, вошёл заново. Пароли хранятся в виде хэшей, для каждого - уникальная соль. Условная схема работы такая: клиент идёт регистрироваться\входить. Попадает в authorizationController, который как камень на распутье: налево пойдёшь - в register попадёшь, направо - login будешь. Оттуда попадает в authorizationService, где живёт бизнес-логика, которая торжественно вручает ему токен. С этим токеном он пытается, допустим, что-то создать. JwtAuthGuard смотрит,  JwtStrategy говорит, что разрешено, и затем пользователь может идти творить что-то в курсах или уроках.

Проверка ролей: RolesGuard проверяет роль, при несоответсвии - никакого создания курса. Также есть проверка владельца, чтобы другие учителя не удаляли чужие курсы. Тут и добавить нечего.

Кэширование: При чтении курса или просмотре списка создаётся кэш для быстрого обращения, при создании, изменении или удалении курса - очищается. Кэш очищается после изменения курса для конкретного изменённого курса и всего списка. Работает всё это добро на redis. Допустим, получаем курсы. RedisService проверяет: а был ли кэш? Если да - держите, нет - идите вы в Mongo. Если пришлось идти за теми же курсами - сохраняются в кэш.

Kafka: нужен для связи между главным сервисом и обработчиком. Картинку загрузили - kafka фиксирует, отправляет задачу обработчику. То есть юзер даёт картинку. Картинка уходит KafkaService.sendImageUploaded(...), оттуда в топик image.uploaded (то есть на сервере есть, но ещё нет наложения всяких вотермарок). Оттуда уходит в Image Worker, обрабатывается через Sharp. Говорит в базу "Да, такая картинка обработана", и идёт в топик image.processed

2. Image Worker

Вся его жизнь - получить задачу на обработку, обработать изображение (сжать и наложить водяной знак), сообщить о том, что картинка обработана. Существует только ради того, чтобы основной сервис не развлекался обработкой картинок.

### Тестовые сценарии

POST {{baseUrl}}/auth/register - Регистрация, будь то учитель или ученик. В теле передаётся имя пользователя, почта, пароль и роль. Результат - в БД написалась почта, пароль с уникальной солью.

POST {{baseUrl}}/auth/login - Вход. Почта и пароль = ответ сервера (временный JWT-токен)

POST {{baseUrl}}/courses - Имя и описание = рождение нового курса с именем, описанием, преподавателем, уроками, студентами, датой создания. Без токена учителя - увы, ничего сделать не выйдет.

GET {{baseUrl}}/courses/{{courseId}} - Получить конкретный курс

PATCH {{baseUrl}}/courses/{{courseId}} - То же самое, но  изменить. Менять может только хозяин.

POST {{baseUrl}}/courses/{{courseId}}/enroll - Только студент может записаться на курс

GET {{baseUrl}}/courses - получить все курсы

DELETE {{baseUrl}}/courses/{{courseId}} - удалить конкретный курс

POST {{baseUrl}}/courses/{{courseId}}/lessons - Учитель может создать урок для конкретного курса. Существование уроков вне курса признано нелогичным

GET\PATCH\DELETE {{baseUrl}}/courses/{{courseId}}/lessons/{{lessonId}} - Просмотреть\Изменить\Удалить урок. Изменять и удалять может только хозяин

GET {{baseUrl}}/courses/{{courseId}}/lessons - Просмотреть все уроки курса.

POST {{baseUrl}}/lessons/{{lessonId}}/images или {{baseUrl}}/courses/{{courseId}}/cover - отправить изображение

GET {{baseUrl}}/images/{{filename}} - Получить картинку

GET {{workerUrl}}/health - узнать, жив ли обработчик
